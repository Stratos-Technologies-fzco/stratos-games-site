# Decisions

Where the build prompt was silent or could not be followed inside a stratos.games box, this is what was chosen and why.

| # | Decision | Why |
|---|---|---|
| 1 | **Offline single-player vs bots**, no Colyseus server | A box on stratos.games is static files only. The server, 20 Hz netcode, matchmaking and regions need hosting the site does not have. Match rules live in `src/core/rules.ts` as pure functions, so they can move to a server later. |
| 2 | One Vite project in `source/`, not a pnpm monorepo | Only one folder is allowed per game, and nothing else needs a workspace. `balance.json` is the single home for every gameplay number. |
| 3 | Built files go in the box root; source stays in `source/` | `npm run build` writes `index.html`, `assets/`, `models/` and `art/` one level up. |
| 4 | Models are copied into `source/public/models/` once and committed | The site needs everything inside the folder (works offline). The originals are untouched. |
| 5 | Terrain: 129 x 129 heightmap, seeded, with flat pads under every building | Same island every run. Buildings never sit on a slope. |
| 6 | Static scenery merged into one mesh per 80 m cell | A few draw calls instead of thousands. One shared vertex-colour material. |
| 7 | Colliders baked by `tools/bake-colliders.mjs` from the GLBs (axis-aligned faces become thin slabs, props use one box) | Gives walls, floors, roofs and stairs without a physics engine. Sloped roofs are not solid. Building yaw is snapped to 90 degrees so boxes stay axis-aligned. |
| 8 | Rays use the shared box colliders plus a terrain march, not three-mesh-bvh | Same code can run on a server later; boxes are already cheap. |
| 9 | Fonts fall back to the system font stack | A web font would be a request to another site. Chakra Petch and Inter apply if installed. |
| 10 | (Replaced by decision 21) The lobby used to show a 3D survivor turntable; it now shows the island picture, as in the mockup | The survivor is still chosen under Survivors and equipped in the Locker. |
| 11 | Region buttons, live ping and leaderboards are left out | There is no server to ping. The lobby says "Offline match". Stats are stored on the device. |
| 12 | Training spawns just outside the Old Sea Fort's south wall | The fort walls block shots at the dummy rows if you spawn inside. |
| 13 | Perks (`perksEnabled`) and the coast buggy (`vehiclesEnabled`) stay off | As specified for v1. |
| 14 | Analytics: only the shared Stratos `track()` (`level_start`, `level_complete`, `game_over`, `weapon_picked`) | Site rule: no other tracking. |
| 15 | No ads yet | The site says ads are not live. Plan: a rewarded "second chance" at the moment of loss. |
| 16 | UI art comes from `Artifacts_GameReady/` through `tools/copy-ui-art.ts`, which writes `public/ui/` and `src/data/ui_assets.json` (the `ui` group of the asset manifest) | The script runs before `npm run dev` and `npm run build`. If the source folder is missing it keeps the copy already committed in `public/ui/`, so the repo builds anywhere. Set `UI_ART_DIR` to point at another folder. |
| 17 | `Artifacts/Image3.png` and every raw image in `Artifacts/` are never used | Its storm dome, chest and blueprint wall look too much like another battle royale. The copy script refuses to copy from any `Artifacts` folder or any `ImageN` file, and a test checks it. |
| 18 | Every image has a `.webp` (used first) and a `.jpg` fallback, through `<picture>` | Only the lobby background is preloaded (1280 on phones, 1920 on desktop, both under 250 KB). Everything else loads when its screen is shown. First load stays far under 20 MB. |
| 19 | Matchmaking is simulated offline: the player count climbs to 24 in about 6 seconds, with a Start now button | There is no server to find players on. The slots are filled by bots and the screen says so ("Bots fill the empty slots"). Only Solo shows it. Training and Demo start at once. |
| 20 | "Harbour Road" (loading image 02) is shown as a High loot spot | It is not a named place on Vayu Island. It matches the Rail Yard side of the map, which is a High tier place, and the drop marker uses its card for the Rail Yard. |
| 21 | The lobby has no 3D survivor and no server list | The picture of the island is the focus, as in the mockup. There are no real servers to list, so that column shows the offline match options instead. The 3D view is not drawn at all while the lobby is open, which saves battery. |
| 22 | The Vanguard outfits are cosmetic only | They change the avatar, the lobby card and the results portrait. **TODO: make a matching low-poly Vanguard model (or recolour a survivor) so the outfit can show in the 3D match.** Until then the in-match model is the selected survivor. |
| 23 | Unlock levels live in `balance.json` under `outfits` (Chrome Vanguard level 10, Ember Vanguard level 5) | The mockup said level 20 for a third card, but the brief gave 10 and 5, so those are used. The equipped outfit is saved in the profile (`sdz-profile`) and a locked outfit is never shown as equipped. |
| 24 | Screen sizes use `em` tied to the screen height | One layout from the 844 x 390 mockups scales up to 1920 x 1080 without separate rules. |
| 25 | The blurred menu picture is set as a CSS variable at start-up | Every panel (Settings, Ranks, Missions, About, pause) shares it, and the file is only fetched when a panel is shown. |
| 26 | `sharp` is a build-time dependency for the share image, and `@types/node` is for types only | `tools/make-og.ts` draws the title on `social/og_base_1200x630.webp` to make `og-image.png` (1200 x 630). Nothing from either goes into the game itself. Node 24 runs the `.ts` tools directly. |
| 27 | Ken Burns: a slow 20 second zoom from 1.0 to 1.05 on background pictures | Switched off when Reduce Motion is on (the setting or the system preference). |
| 28 | After a release, the previous build's hashed files in `assets/` stay on the server for one more release | The game page is cached for 5 minutes. A browser holding the old page asks for the old JS and CSS, so deleting them straight away leaves a blank page. Delete a build only after the next release has been live for a while. |
| 29 | The Old Sea Fort has three gates (north, south, east): one wall segment is left out of each. The west side keeps its wall because the river runs there | The fort was a sealed square, so its 21 loot spawns and its supply kiosk could not be reached by players or bots. |
| 30 | Bots ignore rooftop loot, give up for 40 seconds on a goal they get stuck on, and the path planner avoids cells with a little wall in them | Bot time spent blocked fell from 4.55% to 1.91% in a 3 match test. |
| 31 | Auto graphics starts at Medium on desktop and moves up to High after 6 seconds at 58+ FPS. If High then runs under 42 FPS for 3 seconds it goes back to Medium and stays there for the session | Real shadows used to be reachable only by choosing High by hand. Phones stay on Low under Auto. |
| 32 | After you are eliminated the match goes on and you spectate it: summary card, previous / next player (Q / E, arrows or buttons), drag to orbit, Play Again, Lobby, and a Results button to skip ahead. Stats are recorded once when you are eliminated | Before, the Results screen appeared two seconds after death and spectating never really happened. |
| 33 | Aircraft engine sound, a parachute that pops open and folds away, a landing ring and beam on the ground, and a LANDING line with place, distance and seconds. The prediction matched the real landing spot exactly in a test | Players could not tell where they would land. |
| 34 | Slide: crouch while sprinting at 5.2 m/s or more. It starts at about 8 m/s, fades over 0.75 s, and a jump cancels it | Movement felt flat. |
| 35 | The survivors are rigged humanoids from the CC0 Quaternius Universal Base Characters (Superhero bodies, 65-bone rig), not custom art. Their nude-looking skin texture is thrown away and the surface is repainted by body region into one flat-colour atlas | No final Kiran, Meera, Arjun and Zoya models exist yet. The pack texture is realistic and unclothed, which does not fit the low-poly look. Flat swatches give clean low-poly clothes in each survivor's colours and keep to one 1024 px atlas (512 px on Low) |
| 36 | Animation clips come from the CC0 Quaternius Universal Animation Library (Standard). Its bones are named like the body's, so there is no retargeting. 21 of its 43 clips are kept | The library gives idle, walk, jog, sprint, crouch, jump, roll, pistol aim, reload, death, a sword, a dance and a swim pose. Mixamo needs an Adobe login |
| 37 | **The free library has no rifle clips and no strafe or backward clips.** The 8-direction set is made from forward walk, jog and sprint: played forward or reversed, with the hips turned for each direction and the spine twisted back so the shoulders keep facing the aim. The rifle pose uses the pistol idle, aim (up, level, down) and reload clips with the left hand placed by IK. Hit reacts, idle variations, recoil and lean are code-driven additives | This was your choice ("build it, synthesize gaps"). Real rifle mocap would look better; the system takes it as a drop-in |
| 38 | The animator samples baked clip arrays itself instead of using three.js AnimationMixer. Clips are still loaded from one shared GLB | The mixer cannot do per-bone masks (upper body only), reversed or hip-turned playback of one clip, or exact aim and IK on the same pose. All of them are needed, and it runs in about 0.09 ms per character |
| 39 | Walking, jogging and sprinting each cover their whole speed range (x0.8 to x1.2 of the clip's speed) on their own. Two gaits are blended only in the gaps | Blending walk and jog at the game's 4.5 m/s smeared the foot positions. The game speeds now play one clip, and a planted foot slides 1 to 4 cm per step |
| 40 | Gameplay numbers are unchanged. In particular backpedalling is NOT slowed to x0.75, which the design sheet suggests | You asked not to change gameplay numbers. Backward clips are used at the real speed |
| 41 | Level of detail by distance to the camera: 0 to 25 m full (60 fps, all layers, foot IK, 12k mesh), 25 to 60 m no foot IK (30 fps, 5k mesh), 60 to 150 m base and aim only (10 fps, 1.5k mesh). On phones and Low quality the distances are halved | To protect the animation budget on weak phones. Measured on a desktop only (see the report) |
| 42 | The camera follows the head bone at 70% of its movement beyond a slow average, and bobs at most 2 cm. Not applied with Reduce motion | Design sheet, section 4 |
| 43 | The character is kept in "root-bone space". The root bone is rotated -90 degrees about X, so the pelvis position is stored as (left, backwards, UP) and a clip's pelvis yaw is about local Z | Two bugs came from missing this: height tweaks moved the hips backwards, and strafing rolled the body onto its side. Both are fixed and measured (head height, aim error) in all eight directions |
| 44 | The old procedural survivor stays in the code, used only if the humanoid files fail to load. Its three-stripe trainers are not on the new models, which have plain boots | Safety net; the trainers are gone from gameplay |
| 45 | The drop is faster: about 12.5 s from the plane to the ground instead of about 27 s. Freefall 50 to 65 m/s (sideways 24 to 34 m/s), glider opens at 60 m instead of 80 m, glide falls at 8 m/s instead of 4 m/s and moves forward at 16 m/s instead of 12 m/s | Players asked for a shorter landing. The sideways speeds keep most of the island reachable (about 300 m instead of 400 m). The landing marker uses the same numbers, so it stays right |
